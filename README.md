# Разработка корпоративных приложений — Музей 


## Задание курса

Цель курса — реализация проекта сервисно-ориентированного приложения. В рамках лабораторной работы 1 («Классы») необходимо подготовить объектную модель предметной области и реализовать аналитические запросы в виде unit-тестов с использованием LINQ. Хранение данных на этом этапе осуществляется в памяти в виде коллекций.

## Предметная область

В базе данных музея хранятся сведения об экскурсиях, посетителях и билетах.

- **Выставка:** название, тематика, номер зала, дата начала, дата окончания. Тематика выставки — перечисление (`ExhibitionTheme`).
- **Экскурсия:** дата, время начала, продолжительность, посещаемые выставки.
- **Посетитель:** ФИО, телефон, дата рождения.
- **Билет (контракт):** экскурсия, посетитель, тип билета (взрослый или льготный, перечисление `TicketType`), цена.

## Unit-тесты (аналитические запросы)

1. Топ 5 выставок по количеству посетителей.
2. Список экскурсий с минимальным количеством участников.
3. Сводная информация о посещаемости по каждой тематике выставок за указанный период: общее число посетителей, общая стоимость билетов, среднее, минимальное и максимальное число посетителей в день.
4. Сведения о всех экскурсиях в выбранном зале за заданный период.
5. Сведения обо всех посетителях, купивших билеты на выбранную экскурсию, упорядоченные по ФИО.

## Структура решения

```
Museum.slnx
├── Museum.Domain/          — доменная модель
│   ├── DataSeeder.cs
│   ├── Exhibition.cs
│   ├── ExhibitionTheme.cs
│   ├── Ticket.cs
│   ├── TicketType.cs
│   ├── Tour.cs
│   └── Visitor.cs
└── Museum.Tests/           — unit-тесты (xUnit v3)
    ├── ExhibitionTests.cs
    └── MuseumFixture.cs
```

В `DataSeeder` находятся тестовые данные: по 11 экземпляров каждого доменного класса. Тесты получают общие данные через `IClassFixture<MuseumFixture>`.

## Запуск тестов
